# Telegram Message Cleaner

Приложение Windows с русским тёмным интерфейсом для поиска и удаления **своих** сообщений из одной выбранной группы Telegram. Поддерживает обычные группы и супергруппы, включая форумы.

## Запуск готовой программы

1. Распакуйте ZIP в удобную папку.
2. Запустите `dist/TelegramMessageCleaner.exe`. Установка Python для готового EXE не требуется: интерпретатор и необходимые библиотеки Qt включены в сборку.
3. Введите собственные API ID и API Hash с [my.telegram.org](https://my.telegram.org) → API development tools, затем номер телефона в формате `+79991234567`.
4. Нажмите «Подключиться / получить код». Введите код в приложении; если Telegram запросит пароль 2FA, появится дополнительное поле. Вход осуществляется пользовательским аккаунтом через MTProto, без Bot API.
5. Выберите группу слева. Поиск фильтрует список по названию. Кнопка обновления повторно загружает доступные группы, включая архивные диалоги.
6. Оставьте «Вся история» или выберите даты. Обе даты включаются целиком по местному времени Windows.
7. Нажмите «Сканировать». По умолчанию включён предварительный просмотр: удаление заблокировано. Видны общее число просмотренных сообщений, количество собственных и до 50 примеров.
8. После полного сканирования снимите флажок предварительного просмотра. Нажмите «Удалить все мои сообщения». В окне будут название, ID группы, период и число сообщений. Для подтверждения вручную введите **УДАЛИТЬ**, с учётом регистра, без пробелов.
9. После завершения сохраните итоговый отчёт кнопкой «Экспорт отчёта TXT». Для проверки оставшихся сообщений запустите сканирование снова.

Нажатие «Остановить» прекращает следующие запросы. Уже отправленный запрос удаления отменить нельзя. Остановка действует во время задержек и FloodWait; текущий сетевой запрос может завершаться до 45 секунд. При закрытии окна во время операции приложение сначала запрашивает остановку и корректно закрывает соединение.

### Если вход долго ожидает ответа (обновление 1.0.1)

Экран входа показывает текущий этап и время: подключение (до 20 с), проверка сессии (до 15 с), запрос кода (до 25 с), проверка кода/пароля (до 20 с). Эти этапы последовательные; у каждого свой предел. Многократных скрытых повторов по 45 секунд при входе больше нет. Кнопка «Прервать вход» прерывает ожидание, не отзывает сессию и не удаляет сообщения. Если запрос уже был отправлен, код всё ещё может прийти.

Кнопка «Проверить соединение» доступна без API ID, API Hash и телефона. Она проверяет только TCP-доступность стандартного сервера Telegram на порту 443 из процесса приложения, без входа в аккаунт. Успех этой проверки не гарантирует успешный обмен MTProto или доставку кода. Если используется VPN с выбором приложений, включите для этого EXE маршрутизацию через VPN. Прокси, настроенный только внутри Telegram Desktop, к программе не применяется автоматически.

После ответа Telegram программа показывает сообщённый способ доставки кода. Если это код в приложении Telegram, проверьте служебный чат Telegram на устройстве с активной сессией. При FloodWait выводится время ожидания и блокируется повторная попытка до его истечения. Коды не запрашиваются повторно автоматически по сетевому таймауту.

## Проверка автора и группы

- Собственный ID получается через `get_me()`; требуется подтверждённый пользовательский аккаунт, не бот.
- История выбранной группы читается страницами по 100 сообщений до конца доступной истории или начала периода. Общий лимит на 100/1000/10000 сообщений не установлен. Telegram может скрывать старую историю; программа не может получить то, к чему API не даёт доступа.
- Для каждого кандидата проверяются фактический `peer_id`, `sender_id` и `from_id=PeerUser(собственный ID)`. Признак `out`, автор пересланного сообщения и подпись администратора не заменяют эту проверку.
- Чужие сообщения, сообщения без подтверждённого автора, сообщения от имени канала/анонимного администратора и служебные события исключаются. Пересланное вами сообщение допустимо только при подтверждённом собственном отправителе.
- Перед каждым пакетом удаления снова запрашиваются текущий аккаунт, группа и сами сообщения по ID. При повторе после сетевой ошибки или FloodWait вся проверка повторяется.
- **Для обычных групп Telethon не ограничивает `delete_messages` переданным объектом группы.** Поэтому обязательна проверка реального peer каждого свежепрочитанного сообщения; личные сообщения и сообщения из других групп в запрос не включаются.
- Подтверждение связано с конкретным завершённым сканированием, аккаунтом, ID группы и количеством. Оно используется один раз. Изменение группы/периода или новое сканирование отменяет предыдущий результат. После остановленного или неуспешного сканирования удаление недоступно.
- Используются пакеты до 100 ID и `revoke=True`. Серверные ограничения не обходятся. Между запросами по умолчанию выдерживается 1 секунда (настраивается от 0,2 до 60 секунд). FloodWait ожидается согласно ответу Telegram; не более трёх повторов одной операции. Временные сетевые ошибки повторяются ограниченно.

Список включает доступные группы аккаунта. Покинутые и недоступные группы, личные переписки и вещательные каналы не предлагаются. Старый чат, мигрировавший в супергруппу, автоматически не очищается: программа не расширяет удаление за пределы выбранного peer. Сообщения, появившиеся после завершения сканирования, попадут только в новое сканирование.

## Статистика

Итоговые категории относятся к обработанным кандидатам, их сумма равна «Обработано»:

| Категория | Значение |
| --- | --- |
| Удалено | Получен ответ Telegram на удаление; последующее чтение по ID не вернуло сообщение. Это проверка доступной аккаунту истории, а не независимая проверка устройств всех участников. |
| Пропущено | Повторная проверка не подтвердила автора, группу или период, либо сообщение исчезло до отправки запроса. |
| Ошибки | API отклонил запрос, либо после ответа сообщение всё ещё доступно. |
| Неподтверждённые | Запрос мог выполниться, но нет надёжного ответа или последующей проверки. Потерянный ответ не считается подтверждённым удалением. |
| Не обработано | Кандидаты, до которых операция не дошла из-за остановки или ошибки. |

Отказ удаления одного пакета фиксируется в статистике; программа продолжает следующие пакеты. Неуспешные пакеты не дробятся на отдельные сообщения автоматически. После отказа можно повторно просканировать историю и повторить операцию с новыми результатами.

## Локальные данные

Данные хранятся в `%LOCALAPPDATA%\TelegramMessageCleaner`, независимо от расположения EXE:

- `account.session` — ключ сессии Telegram; возможны временные служебные файлы SQLite. Сессия позволяет доступ к аккаунту: храните её как пароль, не пересылайте. Сохранение справочника пользователей/телефонов Telethon отключено.
- `settings.json` — только размер окна и задержка. API ID, API Hash, телефон, код, пароль, тексты сообщений и выбранные группы сюда не записываются.
- `application.lock` — защита от одновременного запуска двух экземпляров с одной сессией.

API Hash, код и пароль скрыты в полях ввода. После входа реквизиты очищаются из формы; при следующем запуске API ID и API Hash вводятся снова. Активная сессия обычно позволяет обойтись без нового кода. Журнал находится только в памяти и содержит подготовленные статусы; подробные логи Telethon отключены. Предпросмотр текста хранится только в памяти. Экспортируемый отчёт содержит название и ID группы, период и итоговые счётчики, без текста сообщений и реквизитов входа.

Кнопка «Выйти из аккаунта» отзывает текущую сессию через Telegram и удаляет локальный session-файл средствами Telethon. Простое закрытие окна сохраняет сессию. Если сессия уже отозвана в другом клиенте, закройте приложение, удалите локальный `account.session` и войдите снова.

Приложение соединяется с Telegram. Собственных серверов, аналитики, отправки отчётов или автоматических обновлений нет. API ID/Hash используются для официального протокола Telegram; сторонним сервисам они не передаются.

## Исходники и сборка

Требуется Windows x64, Python 3.11+ и совместимые бинарные пакеты зависимостей. Фактически использованная среда и результаты перечислены в `TEST_RESULTS.md`. Готовая сборка рассчитана на Windows 10/11 x64; другие версии Windows отдельно не проверены.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe main.py
.\.venv\Scripts\python.exe -m PyInstaller --noconfirm --clean TelegramMessageCleaner.spec
```

Либо запустите `build.bat`: установка зависимостей, тесты, сборка и автономная проверка запуска EXE выполняются последовательно. Результат — `dist/TelegramMessageCleaner.exe`.

Для проверки EXE без подключения к Telegram:

```powershell
.\dist\TelegramMessageCleaner.exe --self-test .\build\smoke
```

В указанной папке появятся JSON с параметрами встроенного runtime и PNG двух экранов. Этот режим не создаёт Telegram-клиент и не выполняет сетевые запросы.

Структура: `main.py` — запуск и защита второго экземпляра; `ui/` — Qt-интерфейс; `telegram_client/` — модели, проверки и API; `workers/` — отдельный QThread с постоянным asyncio loop и безопасная остановка; `utils/` — настройки; `tests/` — моки API и проверки GUI/runtime.

Все тесты используют искусственные данные и моки. Реальные вход и удаление не выполнялись: реквизиты пользователь вводит только в готовой программе. Исполняемый файл не подписан сертификатом издателя.
