## Автоматические тесты

Команда: `python -m pytest -q --durations=5`.

**66 passed in 4.12s.** Полный вывод: `verification/pytest.txt`.

Проверено на моках, без реального Telegram API:

- Собственный ID берётся из `get_me()`; неподтверждённый аккаунт и бот отклоняются.
- Чужие, анонимные, служебные сообщения, личные переписки и сообщения другого peer исключаются.
- Чтение и пакетная обработка 1 000, 10 000 и **100 001** сообщения. В тестах задержки заменены заглушкой: длительность тестов не является прогнозом скорости реального API.
- Обычные группы и супергруппы; каналы и недоступные сущности отклоняются.
- Автор, peer и период проверяются ещё раз непосредственно перед каждым запросом удаления.
- После FloodWait выполняется ожидание и новая проверка авторства; число повторов ограничено.
- Сетевые сбои, потерянный ответ после фактического выполнения, пустой ответ, усечённая последующая проверка, явный отказ API и ответ без фактического удаления.
- Остановка до удаления, после первого пакета и во время длительного ожидания; следующие пакеты не отправляются.
- Точное слово УДАЛИТЬ, привязка подтверждения к аккаунту/группе/количеству/сканированию, однократное использование и отклонение устаревшего результата.
- Смена группы/аккаунта между этапами; сканирование с ошибкой или остановкой не авторизует удаление.
- Фильтры дат, поиск и снятие выбранной группы, сброс результата при смене периода, режим предпросмотра по умолчанию.
- Пагинация списка групп; исключение каналов, личных переписок и покинутых групп.
- Авторизация кодом, запрос 2FA, выход и локальное размещение сессии — через моки.
- Настоящий QThread с asyncio loop: выполнение фоновой команды и корректное завершение.
- Настройки с белым списком полей; повреждённый JSON; отсутствие секретов из исключений в отображаемом тексте.
- Новые проверки входа: жёсткий предел времени этапа, прерывание зависшего запроса, восстановление нулевого бюджета повторов перед возможным удалением, обработка сетевого сбоя без секретов, сохранение соединения после неверного кода, соблюдение FloodWait, закрытие сокета сетевой проверки без реквизитов, видимость этапа/кнопки отмены и доступность сетевой проверки сразу после первого запуска.

Дополнительно: `pip check` — **No broken requirements found**; импорты и `compileall` прошли.

## Сборка и запуск EXE

Финальная Windows-сборка PyInstaller завершилась с кодом **0**.

Для автономной проверки одна копия `TelegramMessageCleaner.exe` помещена в отдельную папку без исходников и сторонних файлов. Запуск выполнен с `PATH=C:\WINDOWS\System32`, без `PYTHONHOME`, `PYTHONPATH` и переменных путей плагинов Qt.

Команда: `TelegramMessageCleaner.exe --self-test <каталог проверки>`.

Результат:

- Код выхода **0**.
- `sys.frozen = true`.
- `sys.prefix` совпадает с временной директорией распаковки встроенного приложения.
- Qt **6.12.0**, platform plugin **windows**; путь плагинов находится внутри комплекта EXE.
- Экран входа и основной экран отрисованы и визуально проверены: `verification/login.png`, `verification/main.png`.
- Предварительный просмотр включён; кнопка удаления заблокирована.
- Подключений к Telegram и запросов удаления **0**.
- В архиве EXE проверено наличие `python315.dll`, Qt Core/Gui/Widgets, `qwindows.dll`, SQLite и необходимых модулей.

Машина для проверки имеет установленный Python, но изолированный EXE использовал свой runtime и не вызывал внешний интерпретатор. Отдельная чистая виртуальная машина без установленного Python не использовалась.

Машиночитаемые результаты: `verification/self-test.json` и `verification/standalone-launch.json`. Полный список версий среды: `verification/environment-lock.txt`. SHA-256 финального EXE: `dist/TelegramMessageCleaner.exe.sha256`.

Во время первой проверки обнаружена несовместимая ICU DLL, случайно подобранная PyInstaller из другого инструмента в PATH. Сборка исправлена: PATH изолирован, системные API-set/UCRT/ICU библиотеки Windows не подменяются чужими копиями. Успешный автономный запуск выполнен после этой правки.

## Границы проверки

Реальные вход, чтение пользовательских групп и удаление сообщений не выполнялись. API ID, API Hash, коды и пароль пользователя не запрашивались. Доступность истории, права на удаление и реальные ограничения скорости зависят от Telegram и проверяются при использовании приложения владельцем аккаунта. Неподтверждённые результаты не считаются успешными удалениями.

## Изменения 1.0.1

По сообщению пользователя об ожидании входа исправлена недостаточная диагностика: раньше четыре ожидания до 45 секунд могли оставаться скрыты за одним статусом. Вход теперь выполняется отдельными ограниченными по времени этапами со счётчиком, без внешнего цикла повторов Engine.call, и прерывается кнопкой на экране входа. Есть TCP-проверка из процесса приложения без аккаунта и пояснение о маршрутизации VPN. После ответа Telegram отображается сообщённый им способ доставки кода. Во время входа разрешены внутренние переходы Telethon между дата-центрами; нулевой бюджет внутренних повторов для механизма удаления восстанавливается в finally, включая ошибки и отмену.

Скриншот пользователя не позволял определить конкретный этап и не доказывает сетевую блокировку или успешную отправку кода. Успешный вход в реальный аккаунт после обновления не проверялся.
